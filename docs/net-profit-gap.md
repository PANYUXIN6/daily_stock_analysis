# 净利润断层选股（初版）

选股页面选择 **净利润断层** 并运行，或向现有 `POST /api/v1/screening/screen`（后台任务为 `/screen/tasks`）提交 `{"strategy":"net_profit_gap","market":"cn","max_results":5}`。开启选股仍使用 `SCREENING_ENABLED`。这是全市场事件筛选，不是单股 Agent 提示词，也不会让 LLM 决定硬条件是否通过。

## 判定顺序

扫描最近 90 个自然日财报正文或业绩预告事件，与当前 A 股快照交集，排除 ST。先按事件日期批量检查价格必要条件，再对可能符合的股票补完整日线和财务证据；不先按通用因子取 Top-K，以免漏掉低分但符合事件条件的股票。最终必须同时通过：

1. **净利润大幅增长**：以归母净利润为披露口径，同比至少 `50%`。财报用披露值，预告用利润和同比增幅下限；剔除亏损/零基数，不能用扭亏百分比冒充可比增长。最新实际利润若低于事件披露值或预告下限，需重新核实，不入选。
2. **公告下一交易日跳空涨停**：严格取公告日期之后的第一个交易所交易日（周末及休市日跳过，停牌后复牌不顺延）；开盘价、当日最低价都必须高于前一交易日最高价，且收盘价按分四舍五入后等于数据源提供的当日涨停价。仅盘中触板、收盘未封住、只比前收盘价高开但没有完整价格缺口，均排除。不以固定 9.9%/10% 阈值猜测板块涨停制度。
3. **缺口未回补**：下沿为断层前一交易日最高价，上沿为断层日最低价。至少观察断层后 1 个完整交易日；从断层日至观察日，任何一日最低价触及或跌破下沿都排除，即使随后重新上涨。部分进入缺口但没有触及下沿视为尚未完全回补。涨停使用不复权价核对，跨日缺口使用同一锚点的复权因子换算，避免除权除息造成误判。

“未回补”仅描述**截至观察日**的事实，不能证明未来永不回补。初版在上海时区 22:00 后才纳入当天行情，其余时间以此前已完成交易日为止，避免把未收盘或供应商尚未更新的日线当作完整行情。结果明确显示日期与观察天数；不用于盘中预警。

## 业绩口径与基本面

本策略依据财报正文或公司业绩预告判断净利润增长，不使用券商研报预测、机构数量或超预期百分比作为筛选因子。筛选结果表达“净利润大幅增长”，不宣称已经验证“超市场一致预期”。公司业绩预告仍作为财务事件来源；预告利润由万元转换为元，与财报金额口径对齐。

基本面二次门槛使用观察日前已披露的**同报告期实际数据**：

- 归母净利润为正，扣非净利润 / 归母净利润 ≥ `80%`；
- 扣非净利润同比增长、营业收入同比增长、每股经营现金流均为正；
- 不使用以后才公布的财务修订数据；缺项不能由新闻情绪或技术评分补足。

这只能排除一部分明显的一次性利润和质量问题，不等同于完成主营业务研究。行业景气、增长持续性、相对估值与机构买入仍在后续 DSA 基本面和深度分析中核实；通用排序更偏重估值、稳定性和流动性，不额外将“机构大幅买入”设为第四个必需条件。不得从涨停、缺口和缩量直接推断机构建仓或换庄。

**已知限制**：预告只有增长摘要、没有同报告期实际扣非与现金流时暂不入选，可能直到正式财报披露后才具备基本面证据。以后若接入同报告期、可追溯公告时间的预告扣非和现金流证据，再评估扩大覆盖。初版优先避免假阳性，空结果不代表市场绝无这种形态。

## 成交量阶段

量能是说明信息，不代替三个硬条件，也不要求必须走完第三阶段才能入选。断层前 20 个交易日平均成交量为基准；连续一字板期间不误判“已缩量统一”，以第一次日内最低价低于涨停价作为开板日（日线粒度，不能识别分钟内先后顺序）。

- **第一阶段：急剧放大**：开板起前 3 个交易日峰值至少为基准的 2 倍，且观察窗口内没有更大的后续峰值。
- **第二阶段：开始缩小**：开板最初 3 日后的样本分为前后两段，后段均量低于前段，且仍高于断层前基准。
- **第三阶段：趋于稳定**：初期峰值之后至少 5 日，最近 5 日均量高于基准、低于峰值的 65%，成交量变异系数 ≤ 0.2。

其他结果为“尚未开板”“样本不足”“量能形态未确认”。这些是初版的量化研究定义，未经历史收益验证；不将形态解释为资金身份事实，也不使用经典案例名称作为白名单、黑名单或收益保证。

## 配置与证据

复用 `TUSHARE_TOKEN` 和现有 `TUSHARE_HTTP_URL`，不增加独立账号或数据服务。需要财报/预告全市场权限（`income_vip`、`forecast_vip`）以及 `income`、`fina_indicator`、`trade_cal`、`daily`、`adj_factor`、`stk_limit`。接口与权限参考：[利润表](https://tushare.pro/document/2?doc_id=33)、[业绩预告](https://tushare.pro/document/2?doc_id=45)、[财务指标](https://tushare.pro/document/2?doc_id=79)、[每日涨跌停价格](https://tushare.pro/document/2?doc_id=183)。

阈值在 `src/services/screening/strategies/net_profit_gap.yaml` 的 `screening.profit_gap` 中设置，也可沿用 `STRATEGIES_DIR` 加载自定义策略。初版研究参数不是回测所得的最优参数，不能据此承诺收益。

每次运行共用默认 180 秒数据预算，单次 HTTP 请求最多 15 秒；分页完整读取，单次运行内复用相同查询，不重复请求相同日期的全市场日线。权限失败、缺数与超时在结果提示中列明；到达时限保留已验证结果并提示覆盖不完整，不用通用策略填满名额。数据源全部不可用时返回空结果和原因，其他策略继续原有路径。

证据保存在现有结果历史中：`raw.post_analysis_results.net_profit_gap` 包括公告日、报告期、断层日、观察截止日、净利润同比增幅、扣非比例、缺口价格、量能阶段和来源。摘要通过 `post_analysis_summaries.net_profit_gap` 显示，LLM 重排不能覆盖硬证据。证据复用现有通用字典，不新增 API 字段或数据库结构；历史运行保留生成时的证据。

## 验证与回滚

离线验收见 `tests/test_profit_gap_screening.py`，覆盖硬条件正反例、精确触边、除权、净利润增长门槛、预告下限、基本面缺项、数据源失败、分页、真实 pipeline 到响应归一化，以及页面摘要展示测试。

停止使用时选择其他策略；需要从列表移除时在对应策略 YAML 设置 `screening.enabled: false` 并重启服务。历史运行保留，已有策略、API 路径与数据库不需要迁移。
